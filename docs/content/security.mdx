## The trust boundary is "code on this server"

tRadioAI talks to tRadio through exports and local server events only. Any resource on a server can already call any tRadio export (`setChannelPanic`, `disconnectUser`), so what protects the radio is the operator, not the export boundary. The new, powerful hooks (hearing a channel, speaking as a station, answering and ending 911 calls, patching, CAD writes) add one more gate on top: tRadio checks the invoking resource against `Config.integrations` in **tRadio's own** `config/config.lua`, which is **empty by default**:

```lua
Config.integrations = { 'tRadioAI' }
```

No resource hears anything until the operator names it. tRadioAI cannot edit that list and does not try; when tRadio refuses it prints the exact line and waits.

## No net events

tRadioAI registers no network event of its own. Everything crosses as a Lua export or a **local** server event, so there is no client-reachable entry point and no `source` to forget to check. The events it does listen for (`tradio:tap:transmission`, `tradio:station:done`, `tradio:cad:operationResult`, `tradio:911:queued`, `tradio:911:ended`) can be fired by any resource, so each one that carries audio or a result is matched against an unguessable id that tRadio issued (a tap id, a station and request id, a CAD request id) and is dropped otherwise. A resource that fires a fake transmission without the id is ignored.

`tradio:911:queued` and the `tradioai:call` event that hands the dispatcher a call carry no secret, because there is nothing to protect: a fake call makes the dispatcher put a sentence on the air, which is what the event is for. `answer911` and `end911` are verified by tRadio against its own queue.

## Keys

- Provider keys are `server.cfg` convars (`tradioai_<provider>_key`), read **at the moment of use** and never stored in the config object, so a key never sits in something that gets logged or passed over an event.
- A key typed into `config.lua` is **ignored and dropped before the payload is built**, so it does not travel in the config event; the console names the offending field without printing its value.
- `tradioai_status` prints each key as `set` or `not set`. No length, no prefix, no suffix.
- The convar is read by the resource itself. Convars are visible to anyone with console or `server.cfg` access, which is the standard FiveM place for a secret; if that is not enough for your threat model, use a hosted provider's own restricted keys and rotate them.
- The release zip is checked for key-shaped strings (`sk-`, `gsk_`, `xi-`, private-key blocks) before it is built, and for model weights, engine binaries and archives.

## What a hosted provider sees

See [Providers](/docs/tRadioAI/providers#what-leaves-your-server). Audio and transcripts of the channels you list leave the server only if you configure a hosted `transcription` or `text` provider. With everything local, no network call is made at all.

## Child processes

Only the local engine starts a program, and only through **tLib's spawn broker**:

- FXServer needs `add_unsafe_child_process_permission tLib` for the server. That names tLib; tRadioAI is not given a spawn permission of its own.
- tLib does not take a path. It takes the *name* of a program (`llama-server`, `whisper-server`, `piper`) from a catalogue it owns, resolves the binary inside the caller's resource folder itself, binds engines to loopback, and refuses any argument that does not match the declared shape. Nothing in this resource ever names a path.
- Downloaded engines and weights are sha256-checked against the pins in `server/local-engine.lock.json` and a mismatch aborts rather than installs. The pins point at the upstream's own release assets; this project hosts none of them.
- A server that uses only hosted providers needs no permission line and starts no process.

## Consent switches

| Switch | Where | Default |
| --- | --- | --- |
| tRadio may be driven by this resource | tRadio `Config.integrations` | empty: nothing is allowed |
| The dispatcher is on | tRadioAI `Config.enabled` | `false` |
| It answers 911 calls and talks to the caller | tRadioAI `Config.answer911` | `false`, separate from putting a call on the air |
| It may read and write your CAD | tRadio `Config.cad.tools` | tRadio's own default; one switch, not two |
| It stands off a channel a human has | tRadioAI `Config.yieldToDispatcher` | `true` |

## Reporting a problem

Please do not post keys, transcripts of real players or console output with convar values in a public issue. Open an issue describing the behaviour, or contact the maintainer privately for anything that looks like a vulnerability.
